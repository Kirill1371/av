# Тест-кейсы: API qa-internship (Avito Tech 2026)

Набор тест-кейсов для проверки функциональности, авторизации, валидации данных, корректности ответов и безопасности REST API сервиса объявлений.

## Техники тест-дизайна
- Классы эквивалентности и граничные значения (длина логина, значение цены, счетчики статистики).
- Негативное тестирование (невалидные типы данных, некорректные UUID, деформированный JSON).
- Проверка разграничения прав доступа (Access Control Matrix, IDOR).

---

## 0. Сквозной E2E-сценарий (tests/test_e2e_flow.py)

### TC-E2E-001: Сквозной жизненный цикл объявления
- **Тип**: E2E / Интеграционный
- **Предусловия**: Нет
- **Шаги**:
  1. Зарегистрировать нового пользователя через `POST /api/1/register`.
  2. Авторизоваться через `POST /api/1/autorize` и получить Bearer-токен.
  3. Создать объявление через `POST /api/1/item`. Получить `itemId` (UUID).
  4. Запросить объявление по ID через `GET /api/1/item/{id}` и сверить поля (`name`, `price`, `sellerId`).
  5. Запросить статистику v1 и v2 через `GET /api/1/statistic/{id}` и `GET /api/2/statistic/{id}`.
  6. Удалить объявление через `DELETE /api/2/item/{id}`.
  7. Запросить объявление через `GET /api/1/item/{id}` и убедиться, что сервер возвращает `404 Not Found`.
- **Ожидаемый результат**:
  - Все шаги выполняются без ошибок. Объявление создается, успешно запрашивается, а после удаления возвращает 404.

## 1. Регистрация пользователей (POST /api/1/register)

### TC-REG-001: Успешная регистрация с валидными данными
- **Тип**: Позитивный
- **Шаги**:
  1. Отправить `POST /api/1/register` с уникальным `username` (от 3 до 64 символов) и валидным паролем.
- **Ожидаемый результат**:
  - HTTP Status: 201 Created.
  - В ответе возвращается JSON с полями `id` (число) и `username`.

### TC-REG-002: Повторная регистрация существующего логина
- **Тип**: Негативный
- **Предусловия**: Пользователь уже зарегистрирован.
- **Шаги**:
  1. Отправить `POST /api/1/register` с занятым `username`.
- **Ожидаемый результат**:
  - HTTP Status: 409 Conflict.
  - Сообщение об ошибке: `"username is already registered"`.

### TC-REG-003: Регистрация с пустым телом
- **Тип**: Негативный
- **Шаги**:
  1. Отправить `POST /api/1/register` с пустым телом.
- **Ожидаемый результат**:
  - HTTP Status: 400 Bad Request.

### TC-REG-004: Граничные значения длины имя пользователя (3 и 64 символа)
- **Тип**: Граничный
- **Шаги**:
  1. Зарегистрировать логин длиной 3 символа.
  2. Зарегистрировать логин длиной 64 символа.
- **Ожидаемый результат**:
  - HTTP Status: 201 Created в обоих случаях.

### TC-REG-005: Валидация короткого логина (2 символа)
- **Тип**: Негативный
- **Шаги**:
  1. Отправить `POST /api/1/register` с `username` из 2 символов.
- **Ожидаемый результат**:
  - HTTP Status: 400 Bad Request с понятным сообщением об ошибке валидации длины.
  - *(BUG-07: Возвращает "invalid JSON body").*

## 3. Создание объявлений (POST /api/1/item)

### TC-ITEM-001: Создание объявления с валидными данными
- **Тип**: Позитивный
- **Шаги**:
  1. Передать в заголовке `Authorization: Bearer {token}`.
  2. Отправить `POST /api/1/item` с корректным `sellerID`, названием, ценой и статистикой.
- **Ожидаемый результат**:
  - HTTP Status: 200 OK.
  - В поле `status` возвращается строка вида `"Сохранили объявление - {UUID}"`.

### TC-ITEM-002: Создание объявления с чужим sellerID
- **Тип**: Негативный / Проверка доступа
- **Шаги**:
  1. Отправить `POST /api/1/item` с токеном `UserA`, но указать `sellerID` другого пользователя.
- **Ожидаемый результат**:
  - HTTP Status: 400 Bad Request.
  - Сообщение: `"sellerID должен совпадать с идентификатором авторизованного пользователя"`.

### TC-ITEM-003: Создание бесплатного товара (price = 0)
- **Тип**: Граничный / Бизнес-логика
- **Шаги**:
  1. Отправить `POST /api/1/item` с `"price": 0`.
- **Ожидаемый результат**:
  - HTTP Status: 200 OK.
  - *(BUG-02: Возвращает 400 "поле price обязательно").*

### TC-ITEM-004: Отрицательная цена (price = -500)
- **Тип**: Негативный
- **Шаги**:
  1. Отправить `POST /api/1/item` с `"price": -500`.
- **Ожидаемый результат**:
  - HTTP Status: 400 Bad Request.

### TC-ITEM-005: Нулевая стартовая статистика (likes=0, viewCount=0, contacts=0)
- **Тип**: Позитивный / Граничный
- **Шаги**:
  1. Отправить `POST /api/1/item` с нулевыми счетчиками статистики.
- **Ожидаемый результат**:
  - HTTP Status: 200 OK.
  - *(BUG-02: Сервер отклоняет нули в статистике).*

### TC-ITEM-006: Отрицательные значения в статистике (likes = -10)
- **Тип**: Негативный
- **Шаги**:
  1. Отправить `POST /api/1/item` с `"likes": -10`.
- **Ожидаемый результат**:
  - HTTP Status: 400 Bad Request.
  - *(BUG-03: Сервер принимает отрицательные лайки).*

### TC-ITEM-007: Валидация нечислового значения price ("free")
- **Тип**: Негативный / Проверка типов
- **Шаги**:
  1. Отправить `POST /api/1/item` с `"price": "free"`.
- **Ожидаемый результат**:
  - HTTP Status: 400 Bad Request с понятной ошибкой неверного типа поля.
  - *(BUG-08: Сервер пишет "не передано тело объявления").*

### TC-SEC-002: Проверка на Stored XSS в названии товара
- **Тип**: Безопасность
- **Шаги**:
  1. Отправить `POST /api/1/item` с `"name": "<script>alert('XSS')</script>"`.
  2. Запросить объявление по ID.
- **Ожидаемый результат**:
  - Бэкенд экранирует или удаляет HTML-теги.
  - *(BUG-09: Сервер отдаёт сырой тег script).*

### TC-ITEM-008: Проверка Mass Assignment (лишние поля в DTO)
- **Тип**: Безопасность / Схема
- **Шаги**:
  1. Отправить `POST /api/1/item` с полем `"is_admin": true`.
- **Ожидаемый результат**:
  - HTTP Status: 400 Bad Request.
  - *(BUG-10: Сервер принимает неучтенные поля).*

## 6. Удаление объявлений и безопасность (DELETE /api/2/item/{id})

### TC-DEL-001: Удаление объявления автором
- **Тип**: Позитивный
- **Шаги**:
  1. Выполнить `DELETE /api/2/item/{id}` токеном автора.
- **Ожидаемый результат**:
  - HTTP Status: 200 OK. Объявление больше не находится при GET (404).

### TC-DEL-002: Удаление чужого объявления (IDOR)
- **Тип**: Безопасность / IDOR
- **Шаги**:
  1. Выполнить `DELETE /api/2/item/{id_UserA}` токеном `UserB`.
- **Ожидаемый результат**:
  - HTTP Status: 403 Forbidden.
  - *(BUG-01: Сервер разрешает удаление).*

### TC-DEL-003: Повторное удаление уже удаленного объявления
- **Тип**: Негативный
- **Шаги**:
  1. Повторно вызвать `DELETE /api/2/item/{id}`.
- **Ожидаемый результат**:
  - HTTP Status: 404 Not Found.
  - *(BUG-04: HTTP статус 404, а в JSON ответа статус "500").*

### TC-SEC-001: Запрос защищенных ручек без токена
- **Тип**: Безопасность
- **Шаги**:
  1. Вызвать POST/GET/DELETE ручки без заголовка `Authorization`.
- **Ожидаемый результат**:
  - HTTP Status: 401 Unauthorized.
